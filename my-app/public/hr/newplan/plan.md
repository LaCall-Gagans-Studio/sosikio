## 0. 何を売る LP なのか

### 0.1 旧 LP との断絶

| | 旧 `/hr` | 新 `/hr` |
|---|---|---|
| 商材 | コエの健康診断（離職予兆・毎日のサーベイ＋声の日報） | **probe ダッシュボード ＋ Thinking OS** |
| 訴求 | 「辞表は、ある日突然じゃない」＝恐怖と警告 | **「同じ会議でも、誰の物差しで見るかで、次の一手は変わる」＝視点の獲得** |
| 読者 | 人事・労務（離職率が課題） | **定例と1on1を回すリーダー／組織開発・研修・コンサル提供者** |
| トンマナ | 黒地 × 蛍光イエロー × ハザードストライプ × 極太ゴシック | **オフホワイトの紙 × 明朝の1文 × ヘアライン × 顔料色** |
| 声 | 警告・煽り | **観測記録・書簡** |

旧要素（3キャラ／金間大介教授監修／コエカラ研修／ハザードストライプ／`/hr/demo` のマイク録音デモ）は**すべて撤去**する。素材も参照しない。

### 0.2 大前提 — これは製品ドキュメントではなく **LP**

読者は **probe を知らない**。「Thinking OS」も「気配タグ」も「開示レベル」も、
このページで初めて目にする言葉である。したがって次を鉄則とする。

1. **最初の1画面で「何のサービスか」を言い切る。** 思想・比喩・問いかけから入らない。
2. **内部仕様を売り文句にしない。** 「Reactionカード84枚」「線は1.75px」「ベクトル検索ではなくルール」は
   作り手の自慢であって、買い手の関心ではない。買い手が知りたいのは「自分の何が変わるか」。
3. **専門語は使う前に必ず言い換える。** 本文は平易語（活力／ストレス／話す量のかたより）で通し、
   正式名称（WE／BO／Gini）は §3 の対訳表と画面イメージの中だけに置く。
4. **図には読み方を添える。** 「点ひとつが発言ひとつ」「右上ほど良い」を書く。読者は指標の専門家ではない。
5. **不安に先回りする。** 「監視では？」「評価に使われる？」「メンバーに数値が見える？」は
   聞かれる前に答える。B2B の組織系ツールで最大の失注理由はここ。

### 0.2.1 文体 — 詩にしない

エディトリアルなトンマナは維持しつつ、**文章は業務文書のレジスターで書く**。
両者は両立する。紙の質感で語りかけると、検討資料ではなく読み物になってしまう。

| | ✗ 詩的（読み物の顔） | ✓ 業務（検討資料の顔） |
|---|---|---|
| セクション見出し | 「こんなこと、起きていませんか。」 | 「組織の状態把握における、3つの課題」 |
| 同上 | 「解析が終わると、この画面が届きます。」 | 「解析後に提供されるレポート画面」 |
| 本文 | 「声の変化は、本人が言葉にするより先に出ます。」 | 「発話の変化は自己申告に先行して現れます。」 |
| 締め | 「probe は、そこを見えるようにします。」 | 「いずれも『測れていないこと』に起因する課題です。」 |

- **見出しは体言止め。** 句点で終わる一文の見出しは情緒が乗る。名詞句で止める。
- **問いかけ・呼びかけを使わない。** 「〜ませんか」「〜てみてください」は Hero とタブ操作の案内に限る。
- **例外は Hero の1文だけ。** ここだけは明朝で言い切ってよい。ページ全体で1回に限る。

### 0.2.2 書体 — 明朝は1箇所だけ

見出しまで明朝にすると、サイト全体が読み物の顔になる。役割を分ける。

| 用途 | 書体 | クラス |
|---|---|---|
| Hero の主張（ページに1つ） | 明朝 | `.hr-statement` |
| 主要数値・判定ラベル | 明朝 | `.hr-display` |
| セクション見出し以下すべて | ゴシック（tight tracking） | `.hr-title` / `.hr-heading` |

### 0.2.3 LP としての体裁

読み物と製品LPを分けるのは、装飾ではなく**構造**である。以下を必ず入れる。

- **セクション通し番号**（`01 ISSUES` … `11 CONTACT`）— 順序のある資料に見える（`.hr-eyebrow`）
- **バッジ / 小札** — 分類軸を明示する（`.hr-badge`）
- **比較表** — 従来手法との判断軸ごとの対比。購買検討で最も参照される
- **導入前後の対比** — 効果を before / after で示す
- **中間 CTA**（`MidCTA`）— 最下部まで到達しない読者の受け皿
- **CTA の直後に安心材料** — 「2営業日以内にご連絡」「無料」など摩擦を下げる一行

### 0.2.4 図は必ず「読み取り」と「打ち手」をセットで出す

**グラフを置いただけでは、何も伝わらない。** 読者は指標の専門家ではなく、
「で、これを見て何をすればいいのか」が分からなければ、その図は無いのと同じ。
すべての図の直後に `ChartReading` を置き、次の2つを分けて言い切る。

1. **読み取れること（事実）** — 番号付きで2〜3件。数値を必ず引用する
2. **このあと取る打ち手（行動）** — 1文。accent の縦罫で囲い、事実と視覚的に分ける

**データは読み取りやすさを優先して整形してよい。** 実データの生々しさより、
「何が読めるか」が一目で分かることを優先する。ただし表示イメージである旨は必ず注記する。

| 図 | 読ませたい筋 |
|---|---|
| 発話単位の分布 | 平均は良好でも、発言者別に見ると危険域とぬるま湯域に各1名いる。**平均だけ見ていると見落とす** |
| セッション中の推移 | 負荷は議題ではなく、論点が定まらない時間帯に集中している |
| セッション間の推移 | 打ち手の**実施前は横ばい、実施後に改善**。効果検証に使える |

セッション間の推移では **欠席回（線を切る）や構成変化マーカーを置かない。**
例外処理の説明が入ると、読ませたい筋（施策の前後）がぼやける。

### 0.2.5 人格の見せ方 — 3体は深く、それ以外は幅で

| 区分 | 見せ方 |
|---|---|
| 標準3体（実行家・戦略家・伴走者） | タブで切替。GAP 表・選ばれた問い・口調まで**すべて出す** |
| それ以外の人格（6体） | 名前と焦点のみを1グリッドに並べる。**区分バッジは付けない**（すべて提供中として扱う） |

- 深く見せる対象を3体に絞ることで、切替の意味（同じ会議 × 違う物差し）が伝わりやすくなる。
- 追加人格は複数並べる。**選択肢の幅がある**ことを示すため。件数は 6 とし、3列・2列・1列のいずれでも空セルが出ないようにする。
- ギャル人格は LP には掲載しない。

### 0.2.6 人格開発を独立セクションで押し出す

出典: `public/hr/newplan/人格AI開発のご提案Ver1.0_20260907更新版.pptx`。
標準人格を「選ぶ」機能に対して、こちらは自社の熟練者を「つくる」提供。**単独セクション（`#persona-dev`）として建てる。**

| 提案書の要素 | LP での置き換え |
|---|---|
| 暗黙知が形式知化されず、後進に伝わらない | 複製の対象（経営者・役員／熟練コンサルタント／評価の高い管理職）を先に明示 |
| 5ステップ（収集 → 分析 → 学習 → 生成 → 確認・追認） | 開発プロセスとして横並び5枚。番号は accent、下に細線 |
| 3つの提供価値（規模拡大／形式知化／データドリブン） | 「開発によって得られるもの」3枚 |
| 体制（北菱電興 × 監修者）・費用 | 3列の帯。**費用は「個別見積もり」とし、提案書の金額はLPに出さない** |

- ThinkingOs 側にあった「自社専用人格の構築」パネルは削除し、`#persona-dev` への導線に置き換える（重複を避ける）。
- 提案書は特定顧客向けのため、**個社名・個人名・金額はLPに転記しない**。

### 0.3 このLPが伝える一本の線

```
「元気そうに見えた人」が辞める／サーベイが機能しない（＝共感）
      ↓
会議を録音するだけで、声から状態が数字になる（＝probe とは）
      ↓
だから、先に気づける・面談準備が要らない・効果が測れる（＝何が変わるか）
      ↓
実際に届く画面はこれ（＝実物で裏取り）
      ↓
数字を「誰の目で読むか」まで選べる（＝Thinking OS ／ 差別化）
      ↓
あなたの役割ならこう使う（＝自分事化）
      ↓
見せる範囲は選べる・評価には使わない（＝不安の解消）
      ↓
次の定例から始められる（＝ハードルの低さ）
```

## 1. トンマナ（`デザイン.md` の要約と、LP への翻訳）

### 1.1 5原則（そのまま守る）

1. **紙であること。** 影を落とさない。角を丸めない。`border-radius: 0`、`box-shadow` 全面禁止。
2. **結論は文で書く。** 各セクションの先頭は数値ではなく明朝の1文。
3. **色は意味である。** UI に色を使わない。色が出たらデータの符号化か注意喚起。**1画面に accent は3箇所まで。**
4. **余白は情報である。** セクション間 96〜128px を臆せず使う。
5. **測定の限界を隠さない。** 「実データではありません」「著者レビュー前（draft）」を明記する。

### 1.2 カラートークン

`probe-app/src/styles/theme.css` を `/hr` スコープへ移植する（`--hr-*` ではなく probe と同名の意味を持つ変数名にし、`.hr-page` 配下で閉じる）。

| 変数 | 値 | 用途 |
|---|---|---|
| `--paper` | `#F7F6F3` | ページ地 |
| `--paper-raised` | `#FFFDFA` | パネル・表・入力欄 |
| `--paper-sunken` | `#EFEDE8` | 沈めた帯 |
| `--ink` | `#171614` | 本文・見出し・反転セクションの地 |
| `--ink-muted` | `#6B6862` | 補助文 |
| `--ink-faint` | `#9C978E` | ラベル・軸ラベル |
| `--rule` | `#DFDBD3` | ヘアライン |
| `--rule-strong` | `#B9B4AB` | 強い区切り・軸線 |
| `--accent` | `#C91E5E` | **赤い点1つ分だけ。** CTA・平均マーカー・注意 |
| `--q-vital` / `--q-burn` / `--q-tepid` / `--q-risk` | `#5A6B3B` / `#AF573C` / `#33506E` / `#171614` | イキイキ／モエスギ／ぬるま湯／危険 |

**禁則:** ボタン／タブ／バッジに色を使わない（活性はインク濃度と下線）。信号色（緑=良／赤=悪）で判定を表さない。グラデーション塗り。

### 1.3 タイポグラフィ

`next/font/google` で読み込み、CSS 変数化する。日本語フォントは `preload: false`。

| 役割 | 欧文 | 和文 | 用途 |
|---|---|---|---|
| Display | `Instrument Serif` 400 | `Shippori Mincho B1` 600/700 | ステートメント・セクション見出し・人格名 |
| Text | `Inter` 400/500/600 | `Noto Sans JP` 400/500/700 | 本文・ラベル・フォーム |
| Mono | `Geist Mono` 400/500 | — | 指標値・バージョン・ID・閾値 |

ユーティリティ（`hr.css` に定義。probe の `globals.css` と同名で揃える）:

```
.statement   Display / clamp(30px,4.4vw,52px) / lh 1.28 / -0.01em / max-w 22ch
.title       Display / clamp(26px,3.2vw,40px)
.heading     Display / clamp(20px,2.2vw,28px)
```

### 1.4 モーション

`デザイン.md §8`「紙は動かない」に従う。

- 許可: `opacity 0→1` ＋ `translateY 8px→0`、400ms、`cubic-bezier(.2,0,0,1)`、`once: true`
- 禁止: パララックス、スクロール連動の連続アニメ、弾む動き、拡大縮小ホバー、線が走るチャート演出
- ホバーはインク濃度の変化のみ（`translate` 禁止）
- `prefers-reduced-motion` で全無効化（`useReducedMotion()`）

- **カットアウト:** `public/leader/accent-*.png`（クリーム地の細密イラスト）。パネル右上に小さく1点だけ

| モバイル追従CTA | `StickyCTA`。ヒーローを抜けたら出し、`#lead-form` が視界に入ったら引っ込める | 最下部まで到達しない読者の受け皿 |

### §5 Thinking OS — 人格切替（**LP の主役 / 双方向**）

- eyebrow: `THINKING OS`
- title: 同じ会議を、5人が別々に読む。
- リード:
  > Thinking OS は、書籍を全文検索する仕組みではありません。
  > 原則（Memory）と、状況→問いの対応表（Reaction Sheet）に蒸留した、**バージョン付きの人格パッケージ**です。
  > 指標が同じでも、物差しが違えば、出てくる問いが変わります。

**固定のセッション条件を1つ置く**（これが「同じ会議」であることの担保）:

```
S E S S I O N   F I X E D
活力（WE） 4.82 ／ ストレス（BO） 3.91 ／ 最大話者シェア 48%
検出された気配 … 発言の偏り ／ リーダーが話しすぎ
```

その下に**人格タブ5つ**（ポートレート＋名前）。選択すると右側が総入れ替えになる。

| 人格 | 副題 | 指摘するのは | 活力 | ストレス | 最大シェア | 版 |
|---|---|---|---|---|---|---|
| 実行家 | 決めた一手を、担当と期限まで削り込む | 何が決まっていないか | 5.0 | 3.6 | 30% | v0.3.0 |
| 戦略家 | 心地よい合意を、前提から疑う | 何が検証されていないか | 4.8 | **4.9** | 40% | v0.3.0 |
| 伴走者 | 人の体力を、成果より先に見る | 誰の状態が先に削られているか | 5.8 | 3.2 | 26% | v0.3.0 |
| 新入社員 | 若手が言えなかった一言を、代わりに置く | 若手が言えなかった一言 | 5.4 | 3.4 | 22% | v0.1.1 |
| ギャル | 全肯定のバイブスで、本音とアゲを引き出す | どこで本音が引っ込んだか | 5.6 | 3.8 | 28% | v0.1.3 |

選択時に出す内容（すべて実データ）:

1. **GAP 表** — `指 標 / 実 測 / 目 標 / G A P / 判 定`。実測は固定、目標は人格ごと。GAP は自動計算し `範囲内 / 注意 / ズレ大` を出す
   - ※ 戦略家だけストレス目標が基準線 4.5 より**上**（緊張は判断の材料）。これが「物差しが違う」ことの決定的な証拠になるので、注釈で明示する
2. **選ばれた Reaction カード** — カード ID、`title`、`リーダーへの問い`、`次の一手`、`避ける反応`

| 人格 | カード | 題 | リーダーへの問い | 次の一手 |
|---|---|---|---|---|
| 実行家 | `EX-010` | 担当になる人が、今日一度も段取りを話していない | この一手を実際に動かす人は、今日どこで話したか？ | 次回の冒頭で、シェアが最も低かった1名に着手の段取りを1つ確認する。 |
| 戦略家 | `ST-006` | 長く話したのは、論点を持っていたからか、立場があったからか | 今日の説明のうち、反論の余地を残して話した部分はどこか？ | 次回、冒頭の説明を1つ事前共有に回し、その時間を反論の受付にあてる。 |
| 伴走者 | `CO-003` | 今日、観察を置く場所が無かった人がいる | 今日いちばん言葉が少なかった人から、事実を1つ聞けるか？ | 次回の冒頭で、シェアが最も低かった1名に「今週いちばん気になったこと」を1つ聞く。 |
| 新入社員 | `NC-005` | 質問を挟む切れ目が、最後まで来なかった | 今日、質問を受ける時間はどこに置かれていたか？ | 次回、説明の途中に1回だけ「ここまでで分からない言葉はあるか」を挟む。 |
| ギャル | `R003` | 偉い人のソロライブ状態になっている | 肩書きというエフェクトが強すぎて、みんなが忖度して黙っちゃってないかな？ | リーダーから一番遠い席の人をあだ名で呼んで、『〜はどう思う？』とタメ口でバトンを渡す。 |

3. **語り口サンプル**（`voiceSample`）— 明朝の引用で1つ。人格差がいちばん短時間で伝わる
4. **メタ行** — `v{version} · 下書き · 原則 {n} / Reaction {n}`

- 注記: > 既定人格3体（実行家・戦略家・伴走者）はプロダクト設計、追加人格2体は個別に構築したものです。いずれも著者レビュー前（draft）の版を掲載しています。

### §6 18の気配タグ

- eyebrow: `SIGNALS`
- title: 場に出ている気配を、18語で名指す。
- リード: 著者は数式を書きません。固定語彙の中から「この場面で効く気配」を選ぶだけ。閾値付けはシステムが担います。
- 4群の表（`--paper-sunken`、密度高め、Mono で閾値を添える）:

| 群 | タグ |
|---|---|
| 指標・ギャップ | ストレス高め / ストレス低め（沈静・平坦） / 活力高め / 活力低め / 理想とのズレが大きい |
| 対話・場の様子 | 発言の偏り / 沈黙が多い / 対立・緊張が強い / 合意が先走り / 論点が散る / エゴの介入 |
| PDCA・連続性 | 前回アクション未確認 / 同じ論点の繰り返し / 初めてのメンバー構成 / 行動が具体化されていない |
| 役割・開示 | リーダーが話しすぎ / メンバーの観察が足りない / 評価に聞こえる危険 |

- 閾値の例（`.num` で3件だけ。全部出すと読めない）:
  `リーダーが話しすぎ … シェア ≥ 40%（強 ≥ 55%）` / `沈黙が多い … 無音比 ≥ 20% または最長の間 ≥ 60s` / `対立・緊張が強い … 怒り ≥ 12%`
- 締め: > ベクトル検索ではなく、ルールで引きます。だから「なぜこの問いが出たか」を後から説明できます。

### §7 人格の作り方

- eyebrow: `AUTHORING`
- title: あなたの判断ロジックを、人格にする。
- リード（pptx §02・§05 の翻案）:
  > 熟練したリーダーやコンサルタントの「私ならこう答える」は、本人の中にしかありません。
  > Thinking OS は、それをインタビューで引き出し、原則と問答表に蒸留し、バージョンを付けて保存します。
  > 品質を保ったまま、見られるチームの数を増やすための仕組みです。
- 2枚組:

**Memory（人格定義）**
- 概要 / probe 内での役割 / 核となる原則 **5〜10** / 会議を見る評価軸 **3〜7**
- 対話スタイル（口調・語彙・指摘の焦点）／ 判断ルール ／ 理想値 ／ 禁止事項 ／ 不確実なときの振る舞い ／ 出典

**Reaction Sheet（状況→問いの対応表）**
- カード **15〜30 枚**。1枚 ＝ 場面 ＋ 気配タグ ＋ 観察する事実 ＋ 最初の反応 ＋ リーダーへの問い ＋ 行動候補 ＋ 避ける反応 ＋ 参照原則

**版と承認**（`.label` の3段）: `下書き（draft）` → `レビュー済み（reviewed）` → `承認済み（approved）`
> 生成された言葉は、本人が確認・追認できる。だから安心して任せられる。

- 導入ステップ（pptx §07 の翻案）: `ヒアリング` → `インタビュー（ナレッジ収集）` → `構造化とレビュー` → `承認・運用開始`

- eyebrow: `DISCLOSURE`
- title: 見せる情報の解像度を、リーダーが決める。

  > そのまま全員に見せれば心理的安全性を損ない、隠しすぎれば意味がない。
  > probe は**同じデータから、開示レベルの違う複数のレポートを発行**できます。

### §9 推移とループ

- eyebrow: `CONTINUITY`
- title: 一回の測定では、何も変わらない。
- リード: probe は定例で使うものです。セッションが積み上がると、「前回の提言が効いたか」がレポートに載ります。
- 小さな折れ線（SVG）: 6セッション分の WE/BO。**3回目は欠席で線を切る**（補間しない）
- 4点（ヘアライン区切り）:

| 見出し | 本文 |
|---|---|
| 会議日で並べる | 取込日ではなく会議日（`recordedAt`）を x 軸にする。日付未設定の点は薄く区別する。 |
| 欠席は補間しない | 参加していない回は線をつながず、「欠」として見せる。個人の前回比は「**前回参加時**比」で出す。 |
| 構成変化に印を付ける | 参加メンバーが変わった回に △ を置く。平均が動いた＝状態が変わった、と誤読させない。 |
| アクション→変化 | 前回合意したアクションと、それに対する今回の変化をレポートの1ブロックにする。 |

- アラート（`.label` ＋ accent の点）: `リスク象限が2回連続` / `特定メンバーの活力が3セッション連続で低下`

### §10 ガードレール（**ページ唯一の暗転**）

- 地: `--ink`、文字 `--paper`。上下 128px。accent は1箇所だけ
- eyebrow: `GUARDRAILS`
- title: 断定しないことを、設計に組み込む。
- 4点:

| 見出し | 本文 |
|---|---|
| 根拠のない所見は生成しない | AI 所見には必ず根拠（発話 ID ＋ 数値）を紐づけます。検証を通らなければ生成そのものを止めます。 |
| リーダーが承認するまで出ない | 生成された所見は下書きです。リーダーが根拠を確認して承認したものだけが、レポートとメンバーに届きます。 |
| 測定の限界を隠さない | 欠損区間は点線、外れ値として除外した点は中空の円、信頼度の低い発話は不透明度を下げて表示します。 |
| 評価には使わない | 判定は性格診断のようなものです。人事評価や健康診断の代わりにはなりません。 |

- 引用（大きめ・明朝）:
  > AI所見は人事評価や診断ではありません。根拠データを確認し、リーダーが承認した内容だけをレポートに使用します。
  （※ probe 本体の画面に常設されている文言）

### §11 導入の流れ・体制

- eyebrow: `ONBOARDING`
- title: まずは、いつもの定例を一回。
- 4ステップ（`.num` ＋ ヘアライン）:
  `01 ヒアリング`（現状の定例・1on1 の運用と、見たい観点を確認）
  `02 データ収集の設計`（対象セッション、録音方法、同意プロセスを確定）

  `開発・提供 … 北菱電興株式会社` / `ナレッジ提供・監修 … 導入企業`
- 注記: > 費用・期間は対象セッション数と人格構築の有無で変わります。詳細は個別にご相談ください。

### §12 FAQ

`<details>` ベース。ヘアライン区切り、アイコンは `+/−` の細線のみ。JSON-LD の `FAQPage` と本文を一致させる。

1. Thinking OS とは何ですか？
   → 会議の指標を読むための「物差し」を人格として持たせた仕組みです。原則（Memory）と、状況→問いの対応表（Reaction Sheet）をバージョン付きで束ねたパッケージで、既定で5体を用意しています。書籍やドキュメントを全文検索する RAG とは異なり、ルールでカードを引くため「なぜこの問いが出たか」を後から説明できます。
2. probe のダッシュボードでは何が見られますか？
   → 会議音声から算出した活力（WE）とストレス（BO）、エンゲージメント3要素、5つのスキル、感情の構成比を、4象限（イキイキ／モエスギ／ぬるま湯／危険）とタイムラインで確認できます。話者ごとの分布、頻出ワード、発話への drill down にも対応しています。
3. メンバーに数値が見えてしまうのが不安です。
   → 開示レベル Lv.0〜4 を選んでレポートを発行できます。Lv.0 は天気予報のような1文だけ、Lv.4 は全員の全指標です。開示レベルはデータ取得層で強制するため、画面側の実装ミスで漏れることはありません。
4. AI が出した内容をそのまま社員に見せるのですか？
   → いいえ。生成された所見は下書きとして保存され、リーダーが根拠を確認して承認したものだけが外に出ます。根拠（発話 ID ＋ 数値）を伴わない所見は生成しません。
5. 自社の判断基準を人格にできますか？
   → できます。インタビューで原則・評価軸・禁止表現・良い例／悪い例を引き出し、Memory と Reaction Sheet に構造化します。作成した人格には版が付き、本人のレビューを経て承認済みになります。
6. 特別な機材は必要ですか？
   → 不要です。普段の定例や1on1の録音データがあれば始められます。

### 4.1.1 和文の幅指定に `ch` を使わない

`max-w-[22ch]` は欧字の `0` 幅基準のため、和文では**約半分の文字数**しか入らない（実測 22ch ≒ 全角10文字）。
見出しの折り返しを文字数で制御したい場合は **`em` を使う**（全角1文字 ＝ 1em）。

```
✗ max-w-[22ch]   → 52px 時 526px ＝ 全角10文字で折れる
✓ max-w-[12.5em] → 52px 時 650px ＝ 全角12文字入る
```

### 4.3 チャート実装方針

すべて **素の SVG**（probe-app と同じ）。ライブラリを追加しない。

- `viewBox` 固定 ＋ `width="100%"`。`preserveAspectRatio` 既定
- 座標はモジュールスコープの定数配列から算出（決定的な値。乱数を使わない＝ SSR/CSR で一致させる）
- グリッド線は原則なし。必要なら `--rule` の破線（`strokeDasharray="2 6"`）を主要目盛りだけ
- 軸線 1px `--rule-strong`、矢印なし
- 凡例ボックスは作らず、系列の端に直接ラベル（direct labeling）
- テキストは `.chart-label` / `.chart-axis`
- `<title>` と `aria-label` を必ず付け、要点を文章で持たせる

### 4.4 `OsSwitchboard` の作り

`'use client'`。状態は選択中の `osId` 1つだけ。

- タブ: `role="tablist"` / 各ボタン `role="tab"` `aria-selected` `aria-controls`。矢印キーで移動できるようにする
- パネル: `role="tabpanel"`。選択変更時は 160ms のフェードのみ（**中身が入れ替わることが伝わればよい。動かさない**）
- GAP は表示時に計算する（`実測 − 目標`）。判定は絶対値で `≤0.3 範囲内` / `≤0.8 注意` / `>0.8 ズレ大`（シェアは `≤0.05` / `≤0.12`）
- 選択中の人格の識別色（`avatar.accent`）は**アバター枠と GAP 行の点にだけ**使う。地には使わない
- 全人格を1つの配列（`os-data.ts`）に持ち、追加時はデータだけ足せばよい形にする
